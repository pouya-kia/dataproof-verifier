The separate complete finite two-table workflow now admits an explicit `LEFT [OUTER] JOIN` on one same-type direct equality. The left table is preserved as a bag; each unmatched left row receives a NULL right tuple. The existing restricted `WHERE` applies after null-extension. `COUNT(*)` therefore counts unmatched rows, while `COUNT(right_column)` does not. Genuine source NULLs and generated NULLs are not presumed distinguishable from a projected value. Compound `ON`, RIGHT/FULL joins, more than two tables, CTEs, derived tables, strings, timestamps and arbitrary dbt SQL remain unsupported. The one-table Z3, Doppelgänger and Proof2Test semantics are unchanged. This is a finite Python search with an independent DuckDB execution reference, not a new symbolic outer-join encoding.

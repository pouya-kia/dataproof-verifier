# DataProof 0.1.0a2 — release-candidate notes (not published)

This document prepares a possible later GitHub Alpha prerelease. It is **not** a tag, release, package-index upload or claim that `0.1.0a2` has already been published. Human approval is required before publishing either source or binary artifacts as a release. The published `v0.1.0a1` release and assets are unchanged.

Compared with `v0.1.0a1`, this candidate adds a separate complete finite two-table NoUndo check with one explicit INNER or LEFT equijoin, restricted SQL three-valued `WHERE`, one or two direct GROUP BY columns, and existing direct aggregates. The Python finite evaluator is checked against DuckDB execution of the accepted original SQL; confirmed witnesses include an independently replayed SQL artifact. The new backend permits at most two rows per table, three columns and three effective values per column, and 500 analytical combined worlds. Its cooperative timeout is **not** an OS hard limit and there is no process memory ceiling. It does not use Z3 for joined queries. Existing one-table NoUndo, Doppelgänger and Proof2Test contracts are preserved.

The [final DataProof-100 comparison](evaluation/dataproof-100-final-coverage.md) has **0/50 original public-origin tasks fully solved unchanged**. Forty-seven of 50 authored controls were exercised; three inadmissible designs were retained. These synthetic checks are not independent adoption or performance evidence. Unsupported syntax includes string domains, arbitrary expressions, CTEs, windows, dbt model graphs and stateful incremental processing. A bounded-negative result is never a universal SQL theorem.

Before any approved public release: verify the exact source commit, clean 3.11/3.12 CI, fresh Wheel and sdist installations, end-to-end CLI demo and replay, full SHA-256 inventory, source/Wheel parity, privacy/license review, and the unchanged old release tag/assets. Publish only with explicit owner authorization; do not infer approval from this candidate document.
